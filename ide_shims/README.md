# ide_shims

Stand-ins for headers that only exist on Linux, so the tree parses and
type-checks in an editor on macOS (or anywhere else without a BPF toolchain).

**Nothing here produces a working binary.** Every declaration is a signature
with no definition. That is the point: clangd only needs to know a symbol's
type to check call sites and offer completion, and a body it could actually
run would be a lie about what the code does. eBPF does not exist off Linux,
and the real headers come from three places that cannot be reproduced on a
workstation:

| Real source | Shimmed here |
|---|---|
| `vmlinux.h`, generated by `bpftool btf dump` from the *running kernel's* BTF | `vmlinux.h` |
| libbpf, both its BPF-side and userspace-side headers | `bpf/*.h` |
| `bpftool gen skeleton`, run over a compiled `.bpf.o` | `kclient.skel.h` |
| Linux-only syscalls | `sys/epoll.h` |

**eBPF is used only where code must run in the kernel**, which in this project
means `src/kclient/` and nothing else. Userspace interception is
`src/uclient/`, an ordinary C++ agent that Frida injects into a live process —
so there is exactly one `.bpf.c` in the tree and exactly one skeleton to shim.

frida-gum is deliberately **not** shimmed. It is a real library with a real
header that installs on a workstation, so an editor can parse
`src/uclient/agent.cpp` against the genuine article; a stand-in would only
misrepresent it. CMake leaves that file out off Linux rather than fake it.

## Scope

Only what this project actually references. The shims were generated by
enumerating the symbols used across `src/` and `tests/`, not by copying
upstream headers, so anything unused is deliberately absent — adding a call
that is real on Linux but missing here will fail to parse until the shim is
extended, which is the correct signal rather than a nuisance.

Three things are worth stating because they are easy to get wrong:

- **`vmlinux.h` structs are truncated to the fields this code reads.** The
  real ones have many more. Field *offsets* here are meaningless; only names
  and types matter, and only for parsing.
- **`kclient.skel.h` lists exactly the maps and programs `kclient.bpf.c`
  defines.** It is hand-maintained, so adding a map or program to that file
  means adding it here too, or the daemon stops parsing.
- **`sys/epoll.h` is a parse-only shim.** macOS uses kqueue; nothing here
  waits on anything.

## What does not need shimming

`src/qcache/`, `src/common/mysql/`, `src/common/valkey.cpp` and
`src/common/session.cpp` are ordinary POSIX C++ and compile natively on
macOS. `qcache` in particular is dependency-free by design, since it runs on
a host where libbpf may not be installed at all.

## Use

CMake wires this up automatically off Linux; see `CMakeLists.txt`. By hand:

    c++ -std=c++20 -fsyntax-only -Iide_shims -Isrc src/agent/dpipes.cpp
